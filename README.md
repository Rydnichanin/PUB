# Alley PUB

Онлайн-магазин еды и доставки на Firebase: витрина, корзина, регистрация клиентов, рабочие кабинеты сотрудников и отдельная главная админка.

## Возможности

- Магазин Alley PUB с пиццей, роллами, бургерами и напитками; товары и цены хранятся в Firestore.
- Акции: скидка на товар и промо-бейдж в меню.
- Регистрация клиентов, личный кабинет и история заказов.
- Касса: очередь заказов, данные клиента, перевод нового заказа в работу и печать чека для кухни.
- CRM клиентов с именем, телефоном и количеством заказов.
- Кабинеты кухни, курьера, диспетчера и операционного администратора.
- Главная админка: статусы и восстановление заказов, каталог, акции, учётные записи и роли, диагностика, настройки подразделений и JSON-выгрузка.
- Независимые переключатели кухни и курьерской доставки.

## Первый запуск

1. Настройте Firebase Web App в `firebase-config.js`.
2. В Firebase Authentication включите вход по email и паролю.
3. Создайте Firestore database и опубликуйте `firestore.rules`.
4. Откройте `index.html` через статический веб-сервер или GitHub Pages.
5. Создайте первого пользователя через Firebase Authentication. Скопируйте его UID и вручную создайте документ `users/{UID}` в Firestore с полями:

   ```json
   {
     "uid": "UID пользователя из Firebase Authentication",
     "name": "Имя руководителя",
     "email": "email руководителя",
     "phone": "",
     "role": "boss",
     "active": true
   }
   ```

6. Войдите этим аккаунтом: появится отдельная «Главная админка». В ней назначьте роли сотрудникам и добавьте товары в меню.

Роль `boss` нельзя получить через регистрацию на сайте. Первого руководителя назначают только вручную в Firebase Console; после этого главный администратор управляет ролями через панель. Для кухни и заведения укажите в профиле сотрудника `restaurantId: "alley-pub"`.

## Локальный запуск

Из папки проекта:

```powershell
python -m http.server 8000
```

Затем откройте `http://localhost:8000`.

## Данные и доступ

Firestore использует коллекции `users`, `customerDirectory`, `orders`, `tariffs`, `restaurants/{id}/menu`, `transactions` и `settings`. Профили клиентов скрыты от остальных клиентов; кассир получает доступ только к отдельной минимальной CRM-карточке, а руководитель — к операционным данным.

Файл Firebase Web config содержит публичные параметры приложения. Приватные ключи сервисных аккаунтов и секреты нельзя помещать в клиентский код. Расчёт денег в браузере требует серверной проверки для реального приёма онлайн-платежей; текущая версия записывает заказ в Firestore и не подключает эквайринг.

## Публикация

Проект является статическим сайтом. Включите GitHub Pages для корня ветки или используйте любой статический хостинг. Правила Firestore публикуйте только после проверки и подготовки резервной копии проекта Firebase.
